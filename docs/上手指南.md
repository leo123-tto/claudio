## 一、10 分钟在自己电脑上跑起来

本地开发一律用**个人版模式**（默认就是），不需要 hub，也不需要 GPU。

### 要装什么

- [Node.js](https://nodejs.org/) 20 或更高（`node -v` 看版本）。
- Git。
- 一个浏览器。Chrome 或 Safari 都行。

### 跑起来

```bash
git clone https://github.com/<你的账号>/claudio.git   # 先在 GitHub 上 fork，再 clone 你自己的
cd claudio
npm install

cp .env.example .env                  # 配置文件，下面说最少填什么
cp -r packaging/default-user user     # 你的口味档案，从空白模板起

npm run ncm                           # 终端 1：起网易云 API（:3000），别关
npm run dev                           # 终端 2：起 Claudio（:8080）
```

浏览器打开 <http://localhost:8080>，点「开始」。

### `.env` 最少填哪些

| 想要 | 要做的 |
|---|---|
| 界面能打开、能点 | 什么都不填。改界面、改样式这样就够看。 |
| DJ 会选歌、说话（出文字） | 要一个「大脑」。最省事：`.env` 填 `DEEPSEEK_API_KEY`（DeepSeek 官方 API，按量付费），然后在网页右上角 ⚙ 把大脑切到 DeepSeek。本机装好并登录了 `claude` CLI 的，也可以切到 Claude。 |
| 真的放出歌来 | 登录网易云：`npm run login:ncm`，用网易云音乐 App 扫码，cookie 会写进你本机 `.env`。 |
| 口播念出声 | 可以不配。没配语音时只放歌，口播只出文字。要配看 [自部署指南](./自部署.md#语音tts)。 |

**没有网易云账号**：界面能开，但基本放不出歌。不登录时搜索很容易被网易云限流，多数歌也拿不到播放地址。建议注册一个网易云小号登录。音源也可以用插件扩展（见下文「音源层」），仓库里不带插件。

**没有 GPU / 没配语音**：完全不影响。默认语音服务连不上时，这期跳过口播、照常放歌。

**跑测试**：`npm test`。全部是 Node 自带的单测，几十秒跑完，不联网、不需要 `.env`。

> 开发时少重启、别反复点「下一首」压测：每次启动和换歌都会向网易云发一串请求，太密会被限流（报 405「操作频繁」），要等一阵才恢复。

## 二、代码地图

```
web/        网页（个人版、公用版同一份）
server/     服务端（Node.js + Express + ws）
prompts/    DJ 人设提示词
user/       你的口味档案（不进仓库）
test/       单测（node --test）
deploy/     容器部署样例
```

### web/：界面一份，播放引擎两个

| 文件 | 管什么 |
|---|---|
| `index.html` | 整个页面的结构。所有按钮、面板都在这里。 |
| `styles.css` | 样式，含手机竖屏 / 横屏 / 折叠屏的适配。 |
| `boot.js` | **启动入口**：先问服务端 `GET /api/mode`，决定露哪些按钮、加载哪个播放引擎。 |
| `app.js` | 个人版播放引擎：两路音乐交叉淡入 + 口播、后台节目、睡眠定时、多设备接力。 |
| `public.js` | 公用版播放引擎：单个 `<audio>` 顺序放、配额、最近听过、账号。 |
| `ui.js` | 两版共用的界面部件：封面 / 背景、对话条、沉浸歌词、进度条、红心。 |
| `lyrics.js` / `subtitle.js` / `say-sync.js` | 歌词滚动、口播字幕、字幕跟语音对齐。 |
| `transitions.js` | 音量包络、交叉淡入。 |
| `window-mode.js` | 沉浸歌词 / 全屏。 |
| `voice-stream.js` | 口播边收边播。 |
| `airplay.js` | 投放按钮显示规则、`?audio=webaudio` 开关。 |
| `handoff.js` | 本机设备号和设备名（多设备接力用）。 |
| `theme.js` | 深色 / 浅色主题初始化（单独成文件，因为公用版不允许内联脚本）。 |
| `apply.html` / `apply.js` | 公用版的申请页。 |

**`/api/mode` 怎么决定露哪些按钮**：`index.html` 里带 `data-cap="xxx"` 的控件默认是藏着的。`boot.js` 拿到服务端回的 `features`，`features.xxx` 为真才露出来。

- 个人版回：`{mode:'personal', features:{settings, dislike, prev, stop, outputs, sleep, voice, meter, webFonts}}`（`server/index.js`）
- 公用版回：`{mode:'public', features:{quota, history, account}}`（`server/public/app.js`）

所以同一个按钮，只要在某一版的 `features` 里打开，就只在那一版出现。

### server/：主要模块

| 模块 | 管什么 |
|---|---|
| `index.js` | 个人版入口：所有 HTTP 接口和 WebSocket（`/stream`）都在这里挂。 |
| `public/` | 公用版：`app.js` 是它的全部接口；进门、设备、额度交给外部 hub（见 [hub-api.md](./hub-api.md)）。 |
| `llm/` | 大脑适配（本地 OpenAI 兼容 / Claude CLI / DeepSeek），`normalize.js` 解析模型返回的 JSON。 |
| `context.js` | 拼提示词：人设 + 口味 + 最近播放 + 天气 + 场景。 |
| `episode-buffer.js` | 后台预备两期节目。 |
| `episode-audio.js` | 把节目里的歌解析成能播的地址。 |
| `filler.js` | 节目没备好时的垫场歌。 |
| `ncm.js` | 网易云：搜索、取直链、取歌词；限流保护。 |
| `sources.js` | **音源层**：网易云拿不到时按插件找备用音源。 |
| `tts/` | 语音：`index.js` 是工厂，`pc5090.js`（自建 Fish 服务）、`fish.js`（Fish 云端）、`say.js`（macOS say，开发用）。 |
| `intent.js` | 暂停、换歌、音量这类短句直接执行，不打模型。 |
| `settings.js` / `secrets.js` | 设置页的读写；密钥只存本机。 |
| `state.js` / `memory.js` | 播放记录、收藏、长期记忆。 |
| `handoff.js` | 多设备接力。 |
| `scene.js` / `weather.js` | 此刻场景、天气（注入选歌提示词）。 |

### 音源层和插件接口

音源可用插件扩展。插件放在数据目录的 `plugins/`（可用 `SOURCE_PLUGIN_DIR` 改），每个插件一个 `.mjs` / `.js` 文件，默认导出：

```js
export default {
  name: '示例音源',
  prefix: 'ex',                // 2–4 个小写字母，歌曲 id 会是 ex123 这样
  hosts: ['media.example.com'],// 音频直链的域名（代理白名单用）
  async search(keywords, { limit, signal }) { return [{ id, title, artist, album, duration }]; },
  async songUrl(id, { quality, signal }) { return { url, format, bitrate, duration } /* 或 null */; },
  async lyric(id, { signal }) { return '[00:01.00]…'; }, // 可选
};
```

没有插件、插件坏了，都只是「没有备用音源」，不影响别的功能。插件不进仓库；仓库里只接受接口本身的改进，**不接受任何具体音源的接入代码**（见 [CONTRIBUTING](../CONTRIBUTING.md#安全红线)）。

## 三、手把手：在播放界面加一个按钮

拿一个假想的「复制歌名」按钮当例子：点一下，把当前歌名和歌手复制到剪贴板。照着现有的「睡眠定时」按钮（`sleepBtn`）抄最省事，下面每一步都可以先去看它是怎么写的。

### 第 1 步：在 `web/index.html` 加按钮

找到播放栏里的 `sleepBtn`，在旁边加一行：

```html
<button class="icon-btn hidden" id="copyBtn" data-cap="copy" type="button" aria-label="复制歌名" title="复制歌名"><svg class="ico"><use href="#i-copy"/></svg></button>
```

- `hidden` + `data-cap="copy"`：默认藏着，哪一版开了 `copy` 才露出来。
- 图标是页面顶部 `<svg>` 里的 `<symbol id="i-…">`，新图标照样加一个 `<symbol id="i-copy">`。
- 不要写 `onclick="…"` 这种内联脚本，公用版的安全策略会拦掉（见「常见坑」）。

### 第 2 步：决定两版都要，还是只给一版

在想要的那一版 `/api/mode` 的 `features` 里加 `copy: true`：

| 给谁 | 改哪里 |
|---|---|
| 个人版 | `server/index.js` 的 `app.get('/api/mode', …)`，**和** `web/boot.js` 里的 `PERSONAL`（老服务没有 `/api/mode` 时的兜底，两处保持一致） |
| 公用版 | `server/public/app.js` 的 `app.get('/api/mode', …)` |

不加的那一版，按钮就一直藏着。

### 第 3 步：写点击逻辑

- 只在个人版：写进 `web/app.js`。仿照 `sleepBtn`：在文件开头的元素 id 列表里加 `'copyBtn'`，然后 `el.copyBtn.addEventListener('click', …)`。
- 只在公用版：写进 `web/public.js`。
- 两版都要、逻辑一样：把函数写进 `web/ui.js` 并 `export`，两个引擎各自 `import` 后接到按钮上。

```js
el.copyBtn.addEventListener('click', async () => {
  const text = `${current.title} - ${current.artist}`;   // current 换成引擎里「当前在放」的那个变量
  try { await navigator.clipboard.writeText(text); } catch { /* http 下可能不给用 */ }
});
```

### 第 4 步：要调后端的话，接口加在哪

纯界面的改动到上一步就完了。要服务端配合时：

- 个人版接口挂在 `server/index.js`（`app.get` / `app.post`），具体逻辑放进 `server/` 下单独的模块，`index.js` 只做接线。
- 公用版接口挂在 `server/public/app.js`，要登录的接口带上 `auth`（照抄 `app.get('/api/history', auth, …)`）。
- 不要在网页里直接请求第三方网站，统一走自己的服务端。

### 第 5 步：本机预览

改了 `web/` 下的文件，浏览器**强制刷新**（Mac `Cmd+Shift+R`，Windows `Ctrl+F5`）就能看到，不用重启服务。改了 `server/` 才要重启 `npm run dev`。

- `index.html` 里引用 `boot.js` / `styles.css` 带着 `?v=数字`，`boot.js` 里有 `const VERSION`（加载 `app.js` / `public.js` 时用）。改了这些文件，**顺手把对应数字加 1**，不然线上用户的浏览器可能还用旧缓存。
- 手机上看，见下一节。

### 第 6 步：补测试

- 纯逻辑（格式化、计算、判断）抽成小函数放进 `web/` 下的模块，在 `test/` 里加 `xxx.test.js`。照抄 `test/player-actions.test.js`：直接 `import` 网页模块，用 `node:test` 断言。
- 改了 `/api/mode`：公用版在 `test/public-mode.test.js` 里有一条断言 `features` 的键，记得一起改。
- 跑 `npm test`，全过再提交。
- 按钮长什么样、点了有没有反应，测试测不到，靠截图：PR 里附手机和电脑的截图。

### 适合上手的小改动

- 手机端交互：按钮点击区域、横屏 / 折叠屏布局、单手操作时常用按钮的位置。
- 主题：浅色主题的细节、配色、对比度。
- 歌词：字号、行距、当前行高亮、沉浸歌词的排版。
- 驾驶模式：大按钮、少操作、看一眼就懂（维护者正在做第一版，上线后可以接着改）。
- 小毛病：某个机型显示不对、文字被截断、动画卡顿。

## 四、在手机上调试

### 用手机打开电脑上的服务

服务默认监听所有网卡的 `8080` 端口。手机和电脑连同一个 Wi-Fi：

1. 查电脑的局域网地址：Mac 用 `ipconfig getifaddr en0`，Windows 用 `ipconfig` 看「IPv4 地址」。
2. 手机浏览器打开 `http://<那个地址>:8080`。
3. 打不开：看电脑防火墙有没有拦 Node。

局域网走的是 http，有几样东西用不了：语音按钮（麦克风）、添加到主屏幕（PWA）、剪贴板之类，浏览器只在 https 下给。要测这些，给服务套一层 HTTPS 反向代理（见 [自部署指南](./自部署.md#对外访问)）。

### iPhone：Safari 远程调试

1. iPhone：设置 → Safari → 高级 → 打开「网页检查器」。
2. Mac：Safari → 设置 → 高级 → 勾「显示网页开发者功能」。
3. 数据线连上 iPhone，在 iPhone 上打开页面，Mac Safari 菜单「开发」→ 你的 iPhone → 选这个页面。能看控制台、改样式、打断点。

### 安卓：Chrome 远程调试

手机开「开发者选项」里的「USB 调试」，连上电脑，电脑 Chrome 打开 `chrome://inspect`。

### 只是看布局：Chrome 设备模拟

电脑 Chrome 按 `F12` 打开开发者工具，点左上角的手机图标（或 `Cmd+Shift+M` / `Ctrl+Shift+M`），选机型、切横竖屏。注意模拟只是改了尺寸，**iOS 的音频限制模拟不出来**，交 PR 前要在真手机上点一遍。

## 五、常见坑

- **iOS 自动播放限制**：第一次出声必须由用户点击触发。新加的「开始播放」类代码，要放在点击事件里直接调用 `play()`，中间别先 `await` 网络请求。
- **iOS 上音量滑块不管用**：iPhone 不让网页改 `<audio>` 的音量，只能用实体音量键。地址后面加 `?audio=webaudio` 可以改走 WebAudio，滑块就能用了，但会没有投放按钮，锁屏能不能继续放要真机看。
- **iOS 锁屏时计时器会被推迟**：定时类逻辑别只靠 `setTimeout`，可以挂在播放进度事件（`timeupdate`）上，现有的睡眠定时就是这么做的。
- **公用版的安全策略（CSP）**：公用版只允许加载自己网站上的脚本。所以 `web/` 里：
  - 不写内联脚本（`<script>…</script>`、`onclick="…"`），脚本一律放单独的 `.js` 文件；
  - 不引外部 CDN、外部字体、外部图片（网易云的封面图除外）；
  - 个人版没有这些限制，所以在个人版里看着好好的，到公用版可能坏掉。
- **公用版在本机起不来**：它要外部 hub 才能进门。改共用界面时你只需要在个人版里验；公用版那一侧由维护者合并前验。按上一条的规则写，一般不会出问题。
- **改了没生效**：先强制刷新；还不行，看是不是忘了把 `?v=` 数字加 1。

## 六、改完之后：提 PR → 上线

1. 按 [CONTRIBUTING](../CONTRIBUTING.md) 提 PR，CI 跑绿，维护者评审。
2. 维护者合并后，由维护者部署到线上公开版。一般会攒几个 PR 一起上，不保证固定时间。
3. 上线后维护者会在 PR 里留言「已上线」和版本号。网站上设置 / 账号面板角落会显示版本号，也可以直接访问 `/api/mode` 看 `version`（版本号显示正在做，上线后就有）。
4. 然后大家在 [公开版](https://dj.ajkb.app) 上就能用到你的改动。
